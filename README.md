# 센터 매출 관리 (gym-ops)

호석님(지점장)의 헬스장 1개 지점 운영을 위한 회원·매출·업무 관리 웹앱입니다.
**이 문서는 대화 기록이 사라져도 새로운 Claude 세션이 이 프로젝트를 곧바로 이어받을 수 있도록 만든 인수인계 문서입니다.**
새 세션에서 이어서 개발할 때는, 이 폴더(zip을 풀어놓은 것) 전체를 업로드하고 "이 프로젝트 README부터 읽고 이어서 개발해줘"라고 요청하면 됩니다.

## 이게 뭔가요

- 프론트엔드: 빌드 과정 없는 순수 HTML/CSS/JS (프레임워크·번들러 없음)
- 백엔드: Supabase (Postgres + Auth + REST API). SDK를 설치하지 않고 `fetch()`로 REST API(PostgREST)를 직접 호출합니다.
- 배포: Vercel에 **드래그 앤 드롭**으로 zip을 올리는 수동 배포 방식 (git 연동 자동배포 아님). 코드를 고칠 때마다 새 zip을 만들어 Vercel 대시보드에서 다시 업로드해야 반영됩니다.
- 권한: Supabase RLS(Row Level Security)로 지점장/트레이너 권한을 서버(DB)단에서 강제합니다. `is_manager()` 함수로 지점장 여부를 판별.

## 파일 구조

|---|---|

| `data.js` | 모든 화면이 공유하는 데이터 함수 모음 (회원/매출/TM/업무/상품/백업 등 API 호출 전부 여기 있음) |
| `style.css` | 공용 스타일 (전부 순수 CSS, 외부 CSS 프레임워크 없음) |
| `index.html`, `login.html`, `signup.html` | 로그인/회원가입 |
| `home.html` | 로그인 직후 첫 화면. 자주 쓰는 메뉴 아이콘 + 지점장 전용 "데이터 백업" 버튼 |
| `dashboard.html` | 대시보드: 만료 임박 현황, 일간/주간/월간 매출 보고, 상품별 재등록 현황, 최근 매출(페이지네이션) |
| `members.html` | 회원 목록(검색+15개씩 페이지네이션) + 회원 상세 모달(정보수정, 장바구니 방식 이용권 판매) + 엑셀 일괄 등록/업데이트 |

| `tasks.html` | 담당자별 업무 리스트 (반복 업무 지원, 15개씩 페이지네이션) |
| `products.html` | 이용권 상품(가격표) 관리, 지점장 전용 등록/수정/비활성화 |
| `pt.html` | PT 관리(트레이너별 시트, 탭 구조): 목표/확정/예상 매출 카드, 주차별 매출 기록/PT 회원 관리/OT1·OT2 관리 탭 |
| `staff.html` | 직원 관리: 전체 직원 목록 + 권한(트레이너 ↔ 지점장) 전환, 지점장 전용 |
| `center-sales.html` | **센터 매출**: FC/PT/올바른(그룹PT)/총매출 카드 + 트레이너별 매출 표 + PT·회원권·올바른·기타(락커·일일권·운동복·양도) 정산표(탭), 지점장 전용 |
| `schema.sql` | 최초 DB 스키마 (테이블 5개: profiles/members/sales/tm_logs/tasks + RLS) |
| `migration_2~31_*.sql` | 이후 추가된 기능들의 마이그레이션. **번호 순서대로 전부 실행되어 있어야** 코드가 정상 동작함 |
| `seed_products.sql` | 이용권 상품 초기 데이터 (마이그레이션 아님, 1회성 데이터 입력용) |

## 지금까지 구현된 주요 기능

- 로그인/회원가입, 지점장·트레이너 권한 분리 (RLS)
- **트레이너 화면 구성**: 트레이너로 로그인하면 상단 메뉴에 홈/대시보드/회원 관리/PT 관리/업무 리스트/직원 관리만 보이고, 매출 입력·만료회원·TM·이용권 관리는 메뉴에서 숨겨짐 (매출 입력·만료회원 관리는 FC 담당 업무라 트레이너는 볼 필요가 없어서 제외. 지점장은 그대로 전체 메뉴가 다 보임). `auth.js`의 `applyRoleNav()` 함수로 각 페이지에서 공통 적용
- 회원 관리: 검색, 등록/수정/삭제, 엑셀 일괄 업로드(기존 타 프로그램 양식 자동 인식 + 간단 양식). 트레이너도 전체 회원을 조회하고 신규 회원을 직접 등록할 수 있음(담당 트레이너는 본인으로 고정). 단, 엑셀 일괄 업로드·회원 삭제·담당 트레이너 재배정은 지점장 전용으로 유지
- 이용권 판매: 비플 참고한 장바구니 방식 (종류선택 → 담기 → 결제(담당자/결제수단/날짜별 상세설정) → 등록)
- 이용권 상품(가격표) 관리 (지점장 전용)
- 매출 입력/조회/삭제, 결제수단 기록
- 만료 예정·만료 회원 TM(연락) 관리, 카테고리별 필터
- 업무 리스트 (담당자 지정, 반복 업무, 완료 체크)
- 대시보드: 만료 임박 현황, 재등록 확률, 일간/주간/월간 매출 보고(총매출/FC매출/PT총매출 카드), 상품별 재등록 현황
- 만료회원·TM 페이지에도 대시보드와 동일한 "헬스이용권·그룹PT 만료 임박 인원 / 이번 달 재등록 확률" 요약 카드 표시 (카드를 누르면 목록이 해당 상품으로 필터됨)
- 회원 등록 팝업(비플 참고)에서 상품을 고르면 시작일 기준 만료일 자동계산 + 금액 자동 채움(직접 수정 가능) + 판매 담당자·판매 시각까지 지정 → 등록과 동시에 매출로도 자동 기록됨 (이용권/그룹PT/개인PT는 "신규"로 기록)
- 홈 화면 (자주 쓰는 메뉴 아이콘 + 지점장 전용 전체 데이터 백업 다운로드). "스케줄러" 타일은 PT 스케줄(`schedule.html`)이 만들어지기 전엔 "준비중" 배지만 걸려 있었는데, PT 스케줄이 생긴 뒤로는 눌렀을 때 바로 그 화면으로 이동함

(트레이너별 매출 표와 같은 4개 항목 분류를 그대로 재사용했고, 사용자가 명시한 회원권·올바른·기타 3개 항목에 더해 개인PT도 같은 표에 포함시켜서 총 4개 항목 전부 결제수단별로 나오게 함 — 필요 없으면 말씀해주시면 뺄 수 있음.)
- **PT 회원 관리 자동 연동(2026-09-01)**: 회원 관리(`members.html`)에서 개인PT를 등록하면서 담당 트레이너를 배정하면, 그 트레이너의 PT 관리(`pt.html`) → "PT 회원 관리" 탭에 이번 달(`period_month`) 기록이 자동으로 생성돼서 바로 보임(기존 "회원 연결" 방식 그대로 `member_id`가 연결된 상태로 생성되어 "🔗 연동됨"으로 표시되고, 잔여횟수도 회원 데이터를 그대로 따라감) — 이제 지점장님이 PT 관리 시트에 따로 회원을 안 넣어줘도 됨. **담당 트레이너를 나중에 변경하면**(회원 상세 모달에서 담당 변경 후 저장), **이번 달 기록만** 예전 담당 트레이너의 시트에서 사라지고 새 담당 트레이너의 시트로 그대로 옮겨감(회원 연결 상태·입력해둔 상담 내용 등 그대로 유지) — **지난 달 이전 기록은 전혀 건드리지 않음**(사용자 확인: "이번 달 기록만 옮기고, 지난 달 기록들은 그대로 냅둬줘"). 관련 함수는 `data.js`의 `ensurePtCareLogForMember()`(등록 시 자동 생성, 이미 이번 달 기록이 있으면 중복 생성 안 함)와 `movePtCareLogToNewTrainer()`(담당 변경 시 이번 달 기록만 이관). Playwright로 (1) 신규 등록+담당 배정 시 자동 생성·표시, (2) 담당 변경 시 이번 달 기록이 정확히 이관되는지, (3) 담당을 다시 원래 트레이너로 바꿔도 미리 심어둔 지난 달(8월) 기록은 전혀 안 바뀌는지까지 전부 검증함.
- **PT 스케줄(`schedule.html`)**: 바디코디 스타일의 주간 시간표. 트레이너별(지점장은 상단에서 트레이너 선택, 트레이너는 본인 것만) 요일×시간(06:00~22:00) 격자에서 빈 칸을 누르면 회원/수업시간(25·50·80분)/메모를 넣어 새 예약을 잡고, 이미 잡힌 칸을 누르면 출석·결석·취소 처리 또는 삭제를 할 수 있음. **출석·결석 처리하면 그 회원의 개인PT 잔여횟수(`members.pt_remaining_sessions`)가 자동으로 1회 차감됨**(둘 다 "수업이 진행된 것"으로 보고 차감 — 결석도 노쇼로 소진 처리) **취소·삭제는 차감 안 되고, 이미 출석/결석으로 차감된 걸 취소하거나 삭제하면 그 1회가 자동으로 복구됨** (모두 처리 전 확인 문구로 몇 회 → 몇 회로 바뀌는지 보여줌). 상단에 그 주 예약/출석/결석/취소 건수 요약 표시, 상태별로 칸 색이 다름(예약=보라, 출석=초록, 결석=빨강, 취소=회색·취소선). ◀▶로 주 단위 이동, "오늘" 버튼으로 이번 주로 복귀

## 로딩 속도 · 안정성 (2026-08-31)

체감 렉/오류를 줄이려고 앱 전반을 손봤음:

- **서로 무관한 API 요청을 순차적으로 하나씩 기다리던 걸 동시에 보내도록 바꿈.** PT 관리(`pt.html`)는 초기 로딩에 프로필/직원목록/회원목록/상담기록/PT 회원 관리/미응답기록/목표까지 최대 7번을 차례로 기다렸었는데, 서로 의존관계 없는 요청들은 `Promise.allSettled`로 한꺼번에 보내도록 바꿔서 체감 로딩 시간이 크게 줄었음 (PT 스케줄 `schedule.html`도 동일하게 개선). 업무 리스트(`tasks.html`)는 담당자 목록(`fetchStaff`)을 두 군데서 중복 호출하던 것도 하나로 합침. 회원 관리(`members.html`)는 "회원 등록" 팝업용 트레이너 목록 조회가 정작 중요한 회원 표 로딩을 막고 있던 걸 풀어서, 회원 표가 트레이너 목록과 상관없이 먼저 뜨도록 함.
- **로그인한 사람 정보(`getMyProfile()`, `auth.js`)를 못 불러오면 화면 전체가 "로딩 중..."인 채로 영영 멈춰버리던 버그를 고침.** 모든 페이지가 맨 처음에 이 함수부터 호출하는데, 여기서 네트워크가 살짝 끊기기만 해도(와이파이 순간 끊김 등) 그 오류를 아무도 못 잡아서 페이지 초기화가 그 자리에서 조용히 멈췄음(사용자 입장에선 "PT 스케줄 화면이 텅 비어서 안 뜬다"처럼 보임). 이제는 실패해도 0.5초 후 자동으로 한 번 더 시도하고, 그래도 안 되면 예외를 던지지 않고 안전하게 넘어가도록 고쳐서, 새로고침 없이도 대부분 저절로 복구됨.
- 위 항목들은 Playwright로 지연 요청/네트워크 실패 상황을 흉내내서 검증함 (예: 요청마다 400ms 지연을 준 상태에서 PT 관리 초기 로딩이 병렬화 전 이론상 2.8초 → 병렬화 후 약 1.1초로 단축, 프로필 조회 첫 시도 실패 후 재시도로 정상 복구 등).
- **PT 관리(`pt.html`)의 "예상 매출" 카드가 지난 달 이전 리드까지 계속 끌어와서 매달 숫자가 잘못 잡히던 버그를 고침.** 주차별 매출 기록 표·재등록/OT 확정 조사·확정 매출 카드는 전부 "상담일 또는 OT일이 이번 달에 걸치는 리드만" 보는데, 예상 매출 카드만 날짜는 안 보고 상태(진행중 여부)만 보고 계산하고 있었음 — 그래서 몇 달 전에 남겨두고 상태를 안 정리한 리드가 있으면, 정작 이번 달 표에는 그 리드가 안 보이는데도 예상 매출에는 계속 잡혔음(트레이너 구분 없이 다 같은 버그). "이번 달에 속하는 리드" 판정을 `isLeadInMonth()` 공용 함수 하나로 합쳐서 표·카드·미니 요약이 전부 같은 기준을 쓰도록 고쳤고, 이제 예상 매출 카드를 눌러 이동하는 주차별 매출 기록 표와 카드 숫자가 항상 서로 맞음.

## 트레이너 입장으로 전체 앱 직접 사용해보며 점검 (2026-08-31)

사용자 요청으로, 트레이너 계정이 되었다고 가정하고 홈 → 대시보드 → 회원 관리 → PT 관리(3개 탭) → PT 스케줄(예약·출석 처리) → 업무 리스트 → 미팅 기록 → 직원 관리까지 실제 화면 흐름을 Playwright로 하나씩 눌러가며 점검함 (모든 페이지·테이블이 서로 연동된 가짜 데이터로 재현: 담당 회원 2명 중 1명은 잔여 12회, PT 예약 1건, 상담 리드 1건, 이미 연동된 PT 회원 관리 기록 1건, 업무 1건).

- **찾아서 고친 버그: 트레이너가 메뉴에는 없는 매출 입력·이용권 관리 화면에 링크 두 곳을 통해 그대로 들어갈 수 있었음.** 트레이너 로그인 시 상단 메뉴(`.topnav`)에서 매출 입력·만료회원·이용권 관리 링크를 숨기는 `applyRoleNav()`가 딱 상단 메뉴 안쪽 링크만 검사하고 있었는데, 그것과 별개로 홈 화면의 "이용권 관리" 바로가기 타일(`home.html`)과 대시보드의 "+ 매출 등록하기" 인라인 링크(`dashboard.html`)에도 똑같은 주소(href)가 걸려 있어서 이 두 곳은 가려지지 않고 그대로 보였음. 게다가 `expiry.html`·`sales.html` 페이지 자체에는 "이 화면은 지점장만" 같은 내부 권한 체크가 전혀 없어서, 트레이너가 이 두 링크만 누르면 메뉴에 없는 화면에 완전히 들어가져서 매출을 입력하거나 이용권 가격을 바꿀 수 있는 상태였음. `auth.js`의 `applyRoleNav()`가 검사하는 범위를 `.topnav a`에서 페이지 전체의 `a[href]`로 넓혀서, 같은 주소를 가리키는 링크면 어디 있든 한 번에 다 가려지도록 고침. Playwright로 트레이너 계정으로 홈·대시보드 화면을 열어서 두 링크가 실제로 안 보이는지 재검증함.
- **점검했지만 문제 없었던 부분들**: PT 스케줄에서 예약을 출석 처리하면 서버 잔여횟수가 정확히 1회 줄고, 그 직후 PT 관리 → PT 회원 관리 탭으로 이동해도 줄어든 횟수가 바로 반영됨 (이번 세션에서 앞서 고친 실시간 연동이 실제로 잘 동작함을 재확인). 회원 관리 검색·상세보기, 업무 리스트, 직원 관리(트레이너는 편집 버튼 없이 조회만 가능), 미팅 기록 모두 오류 없이 정상 동작. OT 관리 탭에 상담만 하고 아직 OT 날짜를 안 잡은 리드가 안 보이는 건 "OT 날짜가 잡힌 사람만 보여준다"는 원래 설계대로였고 실제로는 버그가 아니었음(주차별 매출 기록 표에는 정상적으로 나타남, 값도 다 정확히 들어있는 걸 재확인).

## 배포 방법 (Vercel 드래그 앤 드롭)

1. 이 폴더 전체를 zip으로 압축
2. Vercel 대시보드 → 해당 프로젝트 → zip을 드래그 앤 드롭으로 업로드하면 재배포됨
3. git 연동이 아니므로, **코드를 고칠 때마다 이 과정을 반복**해야 실제 사이트에 반영됨
4. DB 스키마가 바뀌는 변경이면 코드 배포와 별개로 Supabase SQL Editor에서 해당 migration_*.sql을 먼저(또는 같이) 실행해야 함

## 사용자(호석님) 관련 참고사항

- 지점장, 비개발자. Vercel/Supabase SQL Editor는 안내받은 대로 그대로 따라 할 수 있음
- UI/UX 참고 기준으로 "비플(다른 헬스장 관리 프로그램)" 화면을 자주 캡처해서 보여주고 비슷하게 구현해달라고 요청하는 편
- 기능을 만들면 단계별로 스크린샷을 보여달라고 요청하는 경우가 많음 (Playwright로 로컬 렌더링 후 스크린샷 캡처하는 방식 사용 중)
- 변경할 때마다: 코드 수정 → `node --check`로 문법 확인 → 로컬 정적서버(`python3 -m http.server`)+Playwright로 스크린샷 검증 → git commit → zip 재생성 → SendUserFile로 zip과 관련 migration_*.sql, 스크린샷을 함께 전달 → 사용자가 SQL 실행 + Vercel 재배포
